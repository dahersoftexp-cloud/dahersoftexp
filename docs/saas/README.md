# تنفيذ تحويل DaherSoft إلى منتج متعدد الشركات

تاريخ خط الأساس: 2026-10-16. فُحص المشروعان `serverinventoryDaherServer` و`inventoryDaher` بالحالة المحلية، بما فيها التغييرات السابقة غير المحفوظة في Git.

## حالة الدفعة الأولى

نُفذت بعدها دفعة الهوية والعضوية محلياً؛ راجع [سلوك الدخول وخطة الطرح والتوافق](identity-and-tenancy.ar.md). أرقام هذه الفقرة توثق الدفعة الأولى تاريخياً.

نُفذت بعدها دفعة حراسة الإجراءات؛ راجع [صلاحيات API والقراءات المختصرة وAI والحسابات](api-authorization.ar.md). تتضمن حراسة جميع المداخل الحالية، مع بقاء بوابات الإنتاج وحداثة قراءة العضوية والتخصيص والمحاسبة موثقة كعمل لاحق.

**أحدث دفعة:** [إثبات المحاكي وتجهيز فحص staging](emulator-and-staging.ar.md). نجح **120 اختباراً للخادم و6 اختبارات على Firebase RTDB Emulator الفعلي**، بينها استعادة شركة اصطناعية من Gzip وحفظ بصمات الشركات الأخرى وفقدان رد الحفظ. أُضيف مشغّل محاكي يعزل بيئة العملية وفحص إعداد staging مع قراءة اختيارية موثقة دون كتابة. بقيت بيانات هدف staging واعتماده والنسخة الفعلية والاستعادة السحابية مطلوبة. لا نشر أو تغيير لبيانات العملاء.

سبقتها دفعة [كتابة المستودعات والسيارات وحماية التزامن](warehouse-writes.ar.md)، مع كتابة مشروطة وأرشفة ومراجعة نسخ وإسناد سائق مرجعي. نجح فيها بناء المشروعين و25 اختباراً للواجهة؛ لم تتغير الواجهة في دفعة المحاكي.

سبقتها دفعة [مزوّد بيانات الشركة والقراءات المباشرة للهوية](tenant-data-provider.ar.md)، وتشمل إعداد اعتماد Google في الإنتاج ومتطلب Node >=22.19.0. بوابات staging والنسخ والاستعادة والقواعد المنشورة باقية.

نُفذت أدوات المرحلة صفر محلياً:

- `npm test`: يبني TypeScript ثم يشغّل اختبارات `tests/*.test.js` فقط. نجح 34 اختباراً على Node 22.19.0.
- اختبارات HTTP محلية للسلوك المالي الحالي: بيع نقدي، بيع آجل ثم قبض، قراءة القيود والحسابات، رفض حساب غير موجود، ونقل مستودع. تقارن شجرة شركة ثانية والجذر للتأكد من عدم تغييرها في هذه السيناريوهات.
- اختبار تداخل سياقي شركتين عبر `AsyncLocalStorage`.
- مخزن Firebase في الذاكرة يعترض استيراد SDK وإعداد الاتصال قبل تحميل التطبيق؛ لا تُستخدم `.env` أو بيانات Firebase في اختبارات الأعمال.
- جرد ساكن لمسارات HTTP ومراجع البيانات في الكود، وفحص ومقارنة لملفات تصدير JSON/Gzip المحلية.
- إزالة عنوان Render الافتراضي من اختبار الكتابة القديم؛ يتطلب عنوان loopback صريحاً وإقراراً بقاعدة اختبار قابلة للحذف. يتوقف إذا لم يطابق مستخدم الدخول والرمز الشركة الاختبارية.
- منع إقلاع الإنتاج بسر JWT مفقود أو قصير، وتحميل البيئة قبل تهيئة التطبيق. الحد الأدنى 32 بايت؛ يجب أن يكون السر عشوائياً ومحفوظاً في إعدادات الخادم.
- ملفات CI في كل مستودع لتشغيل اختبارات وبناء محليين، دون أسرار Firebase أو نشر. لم تُشغّل GitHub Actions عن بُعد.
- الواجهة: نجحت اختبارات `npm test` الخمسة و`npm run build`. بقيت تحذيرات Vite عن حجم حزم وبعض بيانات Browserslist القديمة، وهي خارج نطاق هذه الدفعة.

**لم يكتمل شرط خروج المرحلة صفر:** لم تُؤخذ نسخة من الإنتاج، ولم تُختبر استعادتها في staging، ولم تُراجع القواعد المنشورة. لم يحصل اتصال بقاعدة العملاء أو نشر أو ترحيل.

## حدود ما تثبته الاختبارات

`tests/helpers/memory-database.js` بديل حتمي محدود، لا يحاكي Security Rules أو تضارب الكتابات أو إعادة محاولات Firebase. اختبارات الشركات تستخدم رموزاً موقعة اصطناعياً وتثبت فصل المسارات لهذه السيناريوهات فقط؛ لا تثبت فحص العضوية أو اكتمال عزل SaaS.

تعالج الدفعة الثانية هوية الترويسات واختيار الشركة غير الموثوق، وتضيف حراسة جلسة وعضوية أمام مسارات API وSocket، مع قراءة الحسابات القديمة دون نقلها. بقيت بوابات قواعد Firebase المنشورة وحداثة القراءة ونسخ الإنتاج واستعادته، وصلاحيات الإجراءات والاستحقاقات والمحاسبة. لا تُستخدم نتائج اختبارات الذاكرة لإعلان جاهزية SaaS الكاملة.

راجع [خطة المراحل](implementation-plan.ar.md) و[إجراء النسخ والاستعادة](baseline-and-recovery.ar.md).

## تشغيل الفحوص المحلية

أحدث دفعة: [تنفيذ حماية العمليات المالية ونتائج اختبارها وحدود الطرح](financial-safety-implementation.ar.md). تتضمن منع التكرار وحد الالتزام والتحقق وحماية السجلات المرحلة وإصلاح فحص أنواع الواجهة. أعداد الفحوص القديمة في هذه الصفحة تخص دفعاتها التاريخية؛ النتائج الحالية في الوثيقة المرتبطة.

من مستودع الخادم:

```powershell
npm test
node scripts/audit-source.cjs --frontend ../inventoryDaher
```

الأمر الثاني يطبع JSON للجرد إلى stdout؛ لا يبدأ الخادم ولا يحمّل `.env` ولا يستورد متحكمات الأعمال. الحقول `tenant-wrapper` و`manual-review-required` تصف مواضع الكود ولا تمنح حكماً أمنياً آلياً. الحساب الساكن لا يشمل مداخل ديناميكية غير قابلة للتحليل.

جرد هذه الدفعة: 72 ملف TypeScript في الخادم، و183 في الواجهة، و92 إعلان مسار API في 22 مجموعة، بالإضافة إلى مسار الصحة. عُثر على 185 موضع مرجع بيانات، منها 8 باستخدام `rootRef` و9 باستخدام SDK مباشرة (وتشمل تنفيذ الغلاف نفسه). تُعاد الأعداد عند تغيير المصدر.

## شرط النشر الجديد

في الإنتاج يجب ضبط `NODE_ENV=production` و`JWT_SECRET` عشوائي بطول 32 بايت على الأقل. لم تتغير قيمة السر الموجود ولم يُجرَ تدوير للجلسات محلياً. إذا كان السر الحالي ضعيفاً فالتبديل المدروس له سيستلزم إعادة دخول المستخدمين. لا تضع السر في ملفات الواجهة أو Git.

الرجوع عن الدفعة الأولى وحدها لا يحتاج استعادة بيانات لأنها لا تغيّر مخطط الإنتاج. أما دفعة الهوية فلها إجراء توافق موثق قبل الطرح؛ لا يُنشر إصدار قديم لا يفهم الحسابات الجديدة المجزأة. حافظ على السر القوي وحدود الشركات، ولا تعِد الثقة بترويسات العميل كوسيلة رجوع.
